# Reproducibility

Run `make compile`, `make test`, `make income-audit`, `make income-docs`, `make preflight`, then `make pipeline`. The runner repeats compilation/tests and freezes raw/config/code/SQL/supporting-DOCX dependencies before empirical execution. PostgreSQL/PostGIS is authoritative; aggregate CSVs are exports.

`config/qualified_income_decision.json` freezes the explicit qualified income amendment, source and selection hashes, eleven expected source-derived records, formula and mandatory no-income configuration. `make income-audit` applies append-only SQL migration 022, verifies or initially inserts the eleven records, reads exports from SQL, and regenerates the current status report. It refuses conflicting existing records. `make preflight` checks immutable 204-file membership/checksums, 793 legacy archive hashes, source selections/actual deciles/year/formula/provenance/qualification, mandatory no-income settings and SQL equality, alongside candidates/imports/database.

`make income-docs` regenerates current amendment addenda from untouched repository DOCX baselines; all other ZIP members are checked unchanged. Original Downloads attachments are untouched. Historical review DOCX/report/config/code/export copies and checksums remain under `archive/income_investigations`, including the latest expanded municipal review. Historical SQL investigation IDs/records remain unchanged. Historical scripts may regenerate earlier reports; `make income-audit` restores the active decision. No new municipal research or communication is performed.

The full run persists analytical records, saved outer/inner assignments, OOF losses, preprocessing, candidate scores/selections, HC3/wild-cluster inference and paired area bootstrap records in SQL. Mandatory no-income models reuse saved random-five/geographic-eleven and inner-four assignments and the primary thirty-candidate list. Their private artifacts use family `income_robustness`; aggregate reporting includes coefficient, predictive, incremental and per-area comparisons and frozen material-change flags. The complete-run audit requires this matrix and verifies paired observations/outcomes/folds, income omission, candidate equality/budgets, inference and comparisons.

`THESIS_DB_TEST=1 make test` adds database checks; `THESIS_V3_INTEGRATION=1 make test` requires built current analytical inputs. Skips never certify empirical completion. `preflight.json` records readiness; `run_metadata.json` records actual execution/status/errors. `reproducibility_audit.json` is produced only by a successful complete audit. Synthetic smoke output is explicitly artificial. Material OLS predictor missingness above the frozen 5% limit stops until the already planned multiple-imputation/pooling method is specified and validated; no median-imputed inferential fallback is allowed.

The runner refuses populated V3 namespaces rather than erasing data. An interrupted run needs an explicit documented resume/version strategy. Applied SQL migration bytes never change. Raw sources remain immutable; missing income-eligible weights remain NULL.


Execution recovery: the first full run stopped after walking exports on a date-to-JSON metadata serialization error. Its runner, log, SQL metadata and checksums are preserved in `archive/run_recovery/research_v3_20261004T111510Z`. A narrow `--resume research_v3_20261004T111510Z` recovery accepts only that exact recorded error and the completed component prefix through walking exports, unchanged raw/design dependencies, and changes confined to the documented runner repair. It retains original and replacement dependency hashes plus a recovery event, and continues without rebuilding completed data. Scientific failures and other code/config/input drift remain rejected.


A second documented operational recovery corrects the empty date-only/ISO timestamp residual join after both model ladders completed. The source dataset and fitted models are retained unchanged; the copied spatial join must preserve every observation. Recovery requires the exact recorded prefix, runner/spatial-join-only source changes, unchanged design/raw hashes, a passed no-income audit and all four corrected diagnostic streams. Other failures remain rejected. Evidence is archived under `archive/run_recovery/research_v3_20261004T111510Z/spatial_join_failure`.

## Reporting refresh after empirical completion

`make reporting` renders the pastel Version 3 figure suite from the latest completed PostgreSQL run without fitting models, recalculating SHAP, changing the sample, or choosing a new specification. Use `.venv/bin/python -m src.pipeline.render_reporting_figures --run-id research_v3_20261004T111510Z` to select the completed run explicitly. The gallery is `reports/reporting_figures_v3.html`; each figure has high-resolution PNG exports. The figure manifest records captions, SQL source families, map CRS, privacy rules, checksums and coverage of the nine planned figure groups.

The original reporting files, generator sources and empirical audit are preserved in `archive/reporting_refresh/research_v3_20261004T111510Z/before`, with checksums. The original complete-run certificate applies to its original code and output bytes; it does not certify the redesigned figures. A distinct `outputs/tables/reporting/reporting_refresh_audit.json` verifies unchanged raw inputs, scientific source dependencies, frozen analytical dataset, outer/inner assignments and ordered SQL analytical artifact fingerprints before and after rendering. Only the four explicitly named presentation modules may differ from the original source freeze. The completed SQL run and its empirical dependency hashes are retained unchanged.

Listing maps display median values on projected 500 m cells and suppress cells with fewer than five nonmissing plotted values. Counts, missingness and date-key joins are checked without filling values. All map operations use EPSG:25832. The illustrative catchment uses the actual frozen directed walking network at the node on the largest component nearest City Hall +1,500 m east / −1,050 m northing (the fixed V2 public cartographic anchor); it is not a listing-level route or an inferred isochrone polygon. SHAP figures use stored outer held-out contributions. OLS intervals are explicitly identified as HC3, with wild-cluster significance shown separately. Figure transformations are descriptive presentation choices and never feed model fitting or tuning.

The revised pastel figures include full official district-number keys on single-area maps, shared category rows for paired model comparisons, and uncropped labels. The catchment example restores the V2 public anchor and POI-based comparison using the current V3 833 m / 10 minute, 5 km/h definition. All candidate POIs must have stored routing evidence; walking eligibility includes each destination snap connector. Identical destination keys are displayed in both panels, with unreachable points faded in the walking panel. Counts and origin metadata are recorded in `figure_manifest.json`. The first pastel presentation and its certificate are preserved under `archive/reporting_refresh/research_v3_20261004T111510Z/pastel_v1`.

Current presentation preference (4 October 2026): active reporting exports are PNG only. The performance, incremental-gain, OLS-interval, income-sensitivity, robustness, alternative-validation and per-area gain charts place categories on the x-axis and their numeric results on the y-axis. Paired panels share value scales when their units agree, with labels shown once. SHAP importance uses aligned horizontal bars, shortened feature labels and a zero-based contribution axis. Robustness and alternative-validation panels include marker and reference-line legends. Headers use smaller margins; captions follow the measured chart/legend bounds rather than a fixed footer position. Prior presentations and their certificates remain archived under `archive/reporting_refresh/research_v3_20261004T111510Z/pastel_v2` and `pastel_v3`; active PDF/SVG siblings are removed when each PNG is regenerated. Ten figure directories containing only empty `.gitkeep` placeholders were removed; scripts create output directories when needed. No analytical values or scientific definitions change.
